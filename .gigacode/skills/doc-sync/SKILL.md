# Doc Sync

Обновление документации проекта в соответствии с текущим состоянием кода.

## Что обновляет

1. **`docs/modules/*.md`** — документация модулей
2. **`docs/packages/*/README.md`** — документация пакетов
3. **`docs/architecture.md`** — архитектура, паттерны
4. **`docs/README.md`** — навигация
5. **`README.md`** в корнях модулей — пользовательская документация
6. **`docs/testing/*.md`** — если изменились тесты

## Правила работы

**ВСЕГДА** следуй правилам проекта:
- [`docs/guidelines/agent-documentation-guidelines.md`](docs/guidelines/agent-documentation-guidelines.md) — структура, фронтматтер, стиль
- [`docs/coding-standards.md`](docs/coding-standards.md) — конвенции, паттерны
- [`docs/architecture.md`](docs/architecture.md) — зависимости, паттерны проектирования

**Лимиты:** один файл ≤ 200 строк, фронтматтер с `last_updated` и `scope`.

## Сценарии

### 1. Обновление по diff

```bash
git diff HEAD
# или
git diff main...{branch}
```

1. Проанализируй diff → определи затронутые модули
2. Запусти `Explore`-агентов для изменённых пакетов
3. Обнови документацию → проверь кросс-ссылки

### 2. Обновление по ветке

```bash
git diff main...{branch} --stat
```

1. Определи масштаб → запусти `Explore`-агентов **параллельно** для каждого модуля
2. Сравни документацию с фактическим кодом
3. Обнови `docs/architecture.md` и `docs/README.md`

### 3. Обновление модуля

```
обнови документацию для модуля {название}
```

1. Определи путь модуля → запусти `Explore`-агента
2. Обнови: `docs/modules/{module}.md`, `README.md`, `docs/packages/`

### 4. Полное обновление

1. Параллельные `Explore`-агенты для всех модулей
2. Проверь структуру `docs/packages/` на соответствие коду
3. Проверь `docs/architecture.md` и `docs/README.md`

## Workflow

### Шаг 1: Исследование

**ВСЕГДА** используй `Explore`-агентов. Промпт:

```
Исследуй пакет {package-path}. Собери:
1. Публичные классы/интерфейсы/enum/record
2. Назначение каждого (1 предложение), ключевые методы
3. Зависимости от других классов
4. Lombok-аннотации (только если влияют на поведение)
5. Spring Boot автоконфигурация (если есть)
```

### Шаг 2: Сравнение

Сравни результаты с текущей документацией:
- Добавлено/удалено публичных сущностей?
- Изменились сигнатуры?
- Изменились зависимости?

### Шаг 3: Обновление

1. Прочитай текущую версию файла
2. Внеси минимальные изменения
3. Обнови `last_updated`
4. Проверь кросс-ссылки

### Шаг 4: Проверка

Запусти `Explore`-агента для проверки полноты.
