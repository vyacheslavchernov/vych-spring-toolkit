# ru.vych.http.impl.interceptors

Функциональные интерфейсы для перехвата запросов и ответов.

## Публичные интерфейсы

### `RequestInterceptor`

Интерфейс для предварительной обработки HTTP-запросов перед отправкой (добавление заголовков, токенов, логирование).

**Метод:** `void handle(HttpClient client, Request request)` — выполняется **до** отправки запроса. Оба параметра гарантированно не `null`. Интерсептор не может прервать цепочку (возврат `void`), для прерывания — выбросить исключение из `ru.vych.http.impl.exceptions`.

### `ResponseInterceptor`

Интерфейс для последующей обработки HTTP-ответов после получения (валидация, логирование, обработка ошибок).

**Метод:** `void handle(HttpClient client, Response response)` — выполняется **после** получения ответа. Интерсептор видит полный ответ с десериализованным телом и извлечёнными cookies.

## Нюансы

- **Оба интерфейса — функциональные (SAM)**, но не аннотированы `@FunctionalInterface` — можно использовать как лямбды, но компилятор не выдаст предупреждение при добавлении методов.
- **Цепочка интерсепторов** выполняется последовательно через `forEach` — порядок определяется порядком в Spring-списке.
- **`RequestInterceptor` получает `Request` до валидации** — интерсептор может модифицировать запрос до того, как `build()` проверит корректность (однако `Request` уже валидирован в момент вызова `execute()`).
- **`ResponseInterceptor` получает `Response` после парсинга** — интерсептор видит десериализованное тело и cookies.

## Зависимости

- `RequestInterceptor` → `HttpClient`, `Request`
- `ResponseInterceptor` → `HttpClient`, `Response`
