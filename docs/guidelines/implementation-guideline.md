# Руководство по реализации спецификаций

Реализация должна приводить код, тесты и документацию в соответствие со спецификацией.

## 1. Перед реализацией

Изучить:

1. целевую спецификацию;
2. связанные спецификации;
3. существующую документацию;
4. текущую реализацию;
5. существующие тесты.

Определить различия между требуемым и текущим поведением.

Если требование невозможно однозначно определить — использовать `NEEDS_CLARIFICATION` и не додумывать поведение.

## 2. Реализация

Изменить существующий код или добавить новый код так, чтобы он соответствовал спецификации.

Предпочитать минимальные изменения, необходимые для выполнения требований.

Не изменять поведение, не связанное со спецификацией, без необходимости.

## 3. Тесты

Для каждого значимого требования спецификации должен существовать соответствующий проверяемый тест.

Тесты должны покрывать:

- основной сценарий;
- ограничения и бизнес-правила;
- ошибки и исключения;
- важные граничные случаи.

Не изменять существующие тесты только для того, чтобы скрыть регрессию или сделать их проходящими.

## 4. Документация

После изменения реализации проверить связанную документацию.

Обновить `docs/`, если изменилось поведение, архитектура, конфигурация или другой аспект системы, описанный в документации.

Если документация уже соответствует новой реализации — не изменять её без необходимости.

## 5. Завершение

Перед завершением проверить:

- реализация соответствует спецификации;
- все значимые требования покрыты тестами;
- существующие тесты не регрессировали;
- документация соответствует реализации;
- не осталось известных расхождений между `specs/`, `docs/` и кодом.

Если обнаружено расхождение, которое нельзя устранить без уточнения требований, явно указать его как `NEEDS_CLARIFICATION`.
