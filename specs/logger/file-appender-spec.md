# logger-file-appender-spec — FileAppender

## Purpose

Аппендер для записи логов в файлы с поддержкой ежедневной ротации, настраиваемого форматирования и буферизации. Позволяет направлять логи приложения в отдельные файлы без изменения существующей консольной вывода.

## Preconditions

- Logger-система проекта уже поддерживает концепцию аппендеров (`LogAppender`)
- Существующий консольный аппендер работает корректно
- Приложение использует Spring Boot с `LogProperties` для конфигурации логирования

## Inputs

### Конфигурационные свойства

| Свойство | Тип | По умолчанию | Описание |
|---|---|---|---|
| `logger.file.enabled` | `boolean` | `false` | Включить/выключить файловый аппендер |
| `logger.file.dir` | `String` | `./logs` | Директория для файлов логов |
| `logger.file.filename-pattern` | `String` | `app-{date}_{timestamp}.log` | Паттерн имени файла |
| `logger.file.date-pattern` | `String` | `yyyy-MM-dd` | Формат даты в имени файла (DateTimeFormatter pattern) |
| `logger.file.encoding` | `String` | `UTF-8` | Кодировка файла |
| `logger.file.level` | `LoggingLevel` | `INFO` | Минимальный уровень логирования |
| `logger.file.include-entities` | `boolean` | `false` | Включать JSON-представление дополнительных объектов |
| `logger.file.pretty-entities` | `boolean` | `false` | Форматировать ли JSON с отступами |
| `logger.file.buffer-size` | `int` | `8192` | Размер буфера в байтах |

### Форматирование строки лога

Пользователь может настроить формат строки лога через builder-паттерн. Поддерживаемые плейсхолдеры:

| Плейсхолдер | Описание | Пример |
|---|---|---|
| `%date` | Дата/время события | `2026-10-08 14:30:22` |
| `%level` | Уровень логирования (выровнен по левому краю, ширина 5) | `INFO`, `WARN`, `ERROR` |
| `%serviceCode` | Код сервиса в квадратных скобках (выровнен по правому краю, ширина 30) | `[MyService]` |
| `%message` | Основное сообщение | `User logged in` |
| `%entity` | JSON-представление entities | `{"key":"value"}` |

**Ограничение:** Если в кастомном форматтере плейсхолдер `%level` или `%serviceCode` встречается несколько раз, форматирование с фиксированной шириной применяется только к первому вхождению. Остальные вхождения заменяются на значение без форматирования.

**По умолчанию:** формат идентичен консольному аппендеру:
```
<timestamp>     <LEVEL>     [<serviceCode>] : <message> <entities>
```

Пример:
```
2026-10-08 14:30:22    INFO     [MyService] : User logged in
2026-10-08 14:30:23   ERROR     [MyService] : Connection refused
```

### Имя файла

Паттерн имени файла поддерживает переменные:

| Переменная | Описание | Пример значения |
|---|---|---|
| `{date}` | Текущая дата, отформатированная по `date-pattern` | `2026-10-08` |
| `{timestamp}` | UNIX timestamp (секунды) для уникальности имени | `1728391822` |

## Behavior

### Создание и инициализация

1. При `logger.file.enabled=true` аппендер создаётся как Spring Bean
2. При инициализации:
   - Если директория не существует — создаётся автоматически
   - Если относительный путь — разрешается относительно текущего working directory
   - Вычисляется имя файла по паттерну с подстановкой текущей даты и timestamp
   - Если файл с таким именем уже существует, к имени добавляется суффикс `_1`, `_2`, и т.д. до уникальности
   - Файл открывается для дозаписи

### Запись логов

1. При вызове `append(LogEvent)`:
   - Если уровень события ниже настроенного минимального — событие пропускается
   - Если дата в имени текущего файла отличается от текущей даты — открывается новый файл (см. «Ротация»)
   - Событие форматируется в строку по настроенному паттерну
   - Если `include-entities=true`, к сообщению добавляется JSON-представление entities
   - Строка записывается в буфер
   - Буфер flushится после каждой записи
2. Метод `append()` должен быть потокобезопасным

### Ротация

- При каждом вызове `append()` проверяется: совпадает ли дата в имени текущего файла с текущей датой
- Если дата изменилась — открывается новый файл с актуальной датой и новым timestamp
- Старый файл закрывается и больше не используется
- Старые файлы **не удаляются** и **не переименовываются** автоматически

### Закрытие

При уничтожении bean:
1. Буфер flushится
2. Файл закрывается

### Поведение по умолчанию

- Аппендер **выключен** по умолчанию (`enabled=false`)
- Если форматтер не настроен — используется формат по умолчанию, идентичный консольному аппендеру

## Business rules

- Файловый аппендер не заменяет консольный — они работают параллельно
- Кодировка файла всегда UTF-8
- Ротация происходит по дате, а не по размеру файла
- Старые файлы сохраняются на диске без ограничений по количеству и возрасту
- Timestamp в имени файла гарантирует уникальность даже при нескольких запусках в один день

## Errors

| Ситуация | Поведение |
|---|---|
| Директория не существует и не может быть создана | Аппендер не создаётся, bean не регистрируется (возвращается `null` из `@Bean` метода), приложение продолжает работу |
| Нет прав на запись в директорию | Аппендер не создаётся, bean не регистрируется (возвращается `null` из `@Bean` метода), приложение продолжает работу |
| Неверный паттерн даты (`date-pattern`) | Аппендер не создаётся, bean не регистрируется (возвращается `null` из `@Bean` метода), приложение продолжает работу |
| Неверный формат форматтера строки лога (не содержит ни одного поддерживаемого плейсхолдера) | Используется формат по умолчанию, выводится диагностическое сообщение в System.err |
| Файл заблокирован другой процессом | Ошибка записи, bean остаётся в рабочем состоянии для следующих записей |

## Acceptance criteria

- [ ] При `logger.file.enabled=false` файловый аппендер не создаётся
- [ ] При `logger.file.enabled=true` логи записываются в файл по заданному паттерну
- [ ] Директория для логов создаётся автоматически, если не существует
- [ ] При существовании файла с таким же именем добавляется суффикс `_1`, `_2`, и т.д.
- [ ] При смене даты открывается новый файл с актуальной датой
- [ ] Старые файлы не удаляются и не переименовываются
- [ ] Логи с уровнем ниже настроенного минимального пропускаются
- [ ] Entities сериализуются в JSON при `include-entities=true`
- [ ] При `pretty-entities=true` JSON entities форматируется с отступами
- [ ] При закрытии аппендера буфер flushится и файл закрывается
- [ ] Аппендер потокобезопасен
- [ ] Консольный аппендер продолжает работать параллельно

## Examples

### Пример имени файла

Паттерн: `app-{date}_{timestamp}.log`

| Запуск | Результат |
|---|---|
| 2026-10-08 14:30:22 | `app-2026-10-08_1728391822.log` |
| 2026-10-09 10:00:00 | `app-2026-10-09_1728468000.log` |
| Повторный запуск 2026-10-09 (файл существует) | `app-2026-10-09_1728468000_1.log` |

### Пример строки лога

Формат по умолчанию (идентичен консольному аппендеру):

```
2026-10-08 14:30:22    INFO     [MyService] : User logged in
2026-10-08 14:30:23   ERROR     [MyService] : Connection refused : {"userId":123,"ip":"192.168.1.1"}
```

### Пример с кастомным форматтером

Формат: `"%date [%level] %serviceCode - %message"`

```
2026-10-08 14:30:22 [INFO] [MyService] - User logged in
```
